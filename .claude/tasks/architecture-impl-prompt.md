# Промпт для сессии реализации архитектурного плана claude-fleet

Скопировать в новую сессию, открытую в `~/Projects/claude-fleet`.

---

Ты реализуешь план переработки архитектуры claude-fleet из `.claude/tasks/architecture-plan.md`.
План согласован со мной 06.09.2026, развилки в его разделе 5 решены и не переоткрываются:
JSDoc с `tsc --checkJs`, снимок целиком без серверной сортировки, тесты фронта через чистые
модули без DOM-эмулятора, токен-cookie для LAN последним шагом, раскладка `src/<контекст>/`.

## Что прочитать до первой правки

1. `CLAUDE.md` целиком: инварианты это ограничения, не предмет спора. Особенно: без зависимостей
   в сервере (devDependency `typescript` допущена решением по развилке 1), только localhost с
   проверкой Host и Origin, `hooks/report.sh` без логики и форков, ограниченная память любой
   накапливающей структуры, транскрипты только при открытом борде, Node 22 без бандлера.
2. `.claude/tasks/architecture-plan.md`: диагноз, целевое дерево, шаги 0-11 с RED-тестами
   и проверкой вживую, риски (в том числе находки критика: порт в шаге 4b резервируется
   `freePort()` и идёт в `config.port`, `listen(0)` нельзя).
3. `.claude/tasks/audit-2026-09-06.md`: что уже починено, открытые №9 и №12.
4. Код шага, который делаешь, целиком, и его тесты. `node --test` на входе: 132 passed.

## Порядок работы

- Шаги строго по номерам: 0 (CI на несколько job плюс e2e канала), 1 (`domain.js`),
  2 (`config` + `log`), 3 (`sse-hub` + `sse-frames`), 4a, 4b (`createFleet`), 5, 6, 7, 8, 9,
  10 (JSDoc + `tsc --checkJs`), 11 (токен). Переезд файлов в `src/` отдельным коммитом
  через `git mv` перед шагом 2, без правок содержимого, кроме путей импортов.
- Каждый шаг: сначала RED-тест из плана, потом код, потом `node --test` зелёный, потом
  проверка вживую: `launchctl kickstart -k gui/$(id -u)/com.rasulkiller.claude-fleet`, борд
  открыт, событие хука дошло, `/stats` отвечает. Для шагов, трогающих `public/`, ещё Cmd+R
  и headless-скрин изолированной копии. Для шага 5 сквозной прогон канала на копии с
  `FLEET_CHANNEL=1`, живой `~/.claude.json` не трогать.
- Шаг закончен, когда правка CLAUDE.md (карта файлов, инварианты, «что показывает карточка»)
  лежит в том же диффе. Диагноз №10 плана закрывается на шаге 5: инвариант про `ppid`
  переписать как проверенный.
- Коммит на шаг, только по моей команде; сообщение на русском, без подписей и следов
  AI-авторства. Перед тем как просить коммит, показать `git status --porcelain` и итог тестов
  числом из summary-строки.
- Синтетические события только в изолированную копию со своим портом и `FLEET_STATE_FILE`.
  Живой сервер (порт 4319) и `.fleet-state.json` не трогать иначе как перезапуском после
  зелёных тестов. Копию убивать по порту (`lsof -ti :<порт> | xargs kill`).
- Правки файлов репозитория только Edit/Write. Длинное тире не использовать нигде.
- Отклонение от плана (другой модуль, другой порядок, новая зависимость) - докладом до правки,
  не после. Заминка на шаге - закончить остальное шага, что не зависит от неё, и спросить.

## Доки по инструментам (проверено в сессии планирования)

- Node 22.22.3: `process.features.typescript === 'strip'`, `enum` и parameter properties не
  снимаются; проверку типов делает только `tsc`, поэтому JSDoc и `typescript` devDependency.
- `node:test`: `mock.timers.enable({ apis: ['setTimeout', 'setInterval', 'Date'] })` для
  `dropSettledPermissions` и `pruneStale`; `--experimental-test-coverage` с порогами
  `--test-coverage-lines=` для job покрытия, если решишь его завести.
- GitHub Actions: job идут параллельно, `needs` для зависимостей, `concurrency` с
  `cancel-in-progress`, `paths` для job канала, `actions/setup-node` без кэша (lock-файла
  в корне нет).

## Итог каждого шага

решения за мной; отвергнутое с причиной. Сессия раздута или шаг закрыт - предложи handoff
в `.claude/tasks/architecture-handoff.md` (состояние, следующий шаг, тупики с причиной).
