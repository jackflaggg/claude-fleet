# claude-fleet

Локальный дашборд статусов всех сессий Claude Code. В одном окне видно: какая сессия
работает и над чем, какая ждёт твоего вмешательства, какая закончила ход. Цель - убрать
поллинг по вкладкам терминала. Работа идёт строго в WebStorm, тулза этого не меняет:
хуки пассивные, интерактивные сессии в табах остаются как есть.

Пользовательская дока - `README.md`, установка - `install.md`. Этот файл - для работы
над самим кодом.

## Как устроено (поток данных)

```
сессия Claude ──(hook)──> hooks/report.sh ──POST /event──> server.js ──SSE /stream──> public/js/app.js
клик по карточке ──POST /focus/:id──> server.js ──> проект в WebStorm (если .idea + WebStorm-терминал)
                                                     иначе: open -b <bundle-id терминала сессии>
ответ с борда (FLEET_CHANNEL=1) ──POST /channel/message/:id──> server.js ──SSE /channel/commands──> channel/fleet-channel.js ──stdio MCP──> сессия Claude
```

Сессия живёт не обязательно в WebStorm (может быть Alacritty/iTerm/Terminal, напр. `claude`
из home). `report.sh` шлёт bundle-id терминала (`__CFBundleIdentifier`) заголовком `X-Fleet-App`,
и клик возвращает туда, где сессия реально запущена - `resolveFocus()` в `server.js`.

Состояние держится в памяти и локально персистится в `.fleet-state.json` (переживает
рестарт сервера; при ребуте системы сбрасывается по времени загрузки). Наружу с машины
ничего не уходит. Звука нет намеренно - сигнал это сам борд плюс красный favicon-бейдж со
счётчиком и число в заголовке вкладки (видно на фоновой вкладке). Системные уведомления
существуют, но выключены по умолчанию и всегда беззвучные: они для случая, когда борда не
видно вообще (фуллскрин IDE).

## Карта файлов

- `server.js` - `node:http` сервер: SSE `/stream`, приём событий `/event`, `/focus/:id` (фокус WebStorm), `DELETE /session/:id` (убрать карточку руками), `GET /stats` (диагностика: аптайм, RSS, процессорное время, число сессий, открытых бордов и подключённых каналов, размеры событий по типам), раздача HTML/CSS/JS/шрифтов из `public` (`.woff2` с годовым immutable-кэшем, остальное `no-cache`), персист состояния. Читает транскрипты для окна лимита (`scanUsage`, раз в минуту и только пока борд открыт) и проверяет PID всех сессий с известным `processPid` (`scanLiveness`, `process.kill(pid, 0)`, раз в 10 сек и тоже только пока борд открыт). За флагом `FLEET_CHANNEL=1` держит маршруты канала ответа: `GET /channel/commands?pid=` (SSE к процессу канала), `POST /channel/permission-request` (от канала), `POST /channel/permission/:id` и `POST /channel/message/:id` (от борда); снимок тогда несёт поля `channel` и `permission`, реестр каналов ограничен `MAX_CHANNELS`, закрытые в терминале запросы разрешения снимает `dropSettledPermissions` с паузой 3 с. Биндится на `FLEET_HOST:FLEET_PORT`. Грузит `.env` через `process.loadEnvFile` (Node 22, без npm-зависимостей). Держит таймер резервной уборки зомби (`pruneStale` раз в 5 мин). Запись в SSE-клиентов, heartbeat, чтение тела и spawn фокуса обёрнуты в try/catch или `on('error')` - обрыв сокета или отсутствие лаунчера не роняет процесс. Роутинг живёт в `route()`, обёрнутом в try/catch: синхронная ошибка маршрута даёт 500 одному запросу, а не смерть процесса; id из пути берёт `decodeId()` (битое percent-encoding это 400). Все записи в SSE идут через `writeSse()` (лимит буфера нечитающего клиента) и `openSse()` (заголовки, TCP keepalive, heartbeat), рассылка снимка коалесцируется в `broadcast()` таймером `BROADCAST_DEBOUNCE_MS`. Всё, что пишется в `fleet.log`, идёт через `log()` с меткой времени; числовой конфиг читает `envNumber()`, который мусор и ноль тоже пишет в лог.
- `liveness.js` - **чистое ядро быстрой уборки закрытых сессий по PID** (для Claude и Codex одинаково): `pruneClosedSessions` удаляет карточку только после двух последовательных проверок отсутствующего PID. Side effect проверки процесса остаётся в `server.js`, поэтому защита от гонок и bounded-реестр подозрений покрыты тестами.
- `channel/fleet-channel.js` - **прототип ответа с борда**, единственное место с npm-зависимостями (`@modelcontextprotocol/sdk`, `zod`; свой `package.json`, `node_modules` в `.gitignore`). MCP-сервер на stdio с capability `claude/channel` и `claude/channel/permission`, который Claude Code запускает сам на каждую сессию (research preview каналов, см. `install.md`, «Ответ с борда»). Держит SSE к борду за командами и пересылает борду `permission_request`. К карточке привязывается по `process.ppid` (тот же PID, что `$PPID` у hook-команды). stdout занят транспортом MCP, лог только в stderr. Выходит при закрытии stdin (`transport.onclose` плюс `end`/`close` самого stdin): проверено, процесс уходит за миллисекунды, открытый SSE к борду его не держит.
- `focus.js` - **чистое ядро решения «куда вернуть по клику»**: `resolveFocus(card, { launcher, app, isProjectDir })`. Проверка «папка это проект» приходит параметром (как `now` в `state.js`), поэтому матрица случаев (терминал IDE / обычный терминал / нет лаунчера / ничего не известно) покрыта тестами без файловой системы. Здесь же живёт фолбэк `open -a <app> <cwd>`, когда CLI-лаунчера на машине нет.
- `guards.js` - **чистое ядро ограничителей**: `buildAllowLists()` собирает разрешённые Host и Origin, `isAllowedHost()` / `isCrossSite()` решают, пускать ли запрос, `boundedKey()` даёт ключ для счётчика с ограниченным числом строк. Вынесено отдельно, потому что оба ограничения коварны одинаково: если их снять, на вид ничего не сломается - борд продолжит работать, просто наружу утечёт содержимое сессий или процесс начнёт пухнуть. Всё чистое, покрыто тестами.
- `usage.js` - **чистое ядро окна лимита**: `collectStamps(chunk, stamps)` вытаскивает метки времени запросов из куска транскрипта, `foldStamps()` сворачивает их в текущее окно, `describeWindow()` готовит его для борда, `isFreshTranscript()` решает, стоит ли открывать файл. Лимит привязан к **аккаунту, а не к проекту**: все сессии во всех папках плюс claude.ai жгут одну квоту, поэтому окно на борде одно и живёт в шапке. Точной телеметрии лимита нет (как и у статусов) - считаем по локальным транскриптам `~/.claude/projects/**/*.jsonl`, где у каждой записи ассистента есть `timestamp`. Расход в токенах отсюда НЕ считаем: сессии из браузера и с телефона в локальные файлы не попадают, и число было бы занижено незаметно для глаза.
- `state.js` - **чистое ядро**, `applyEvent(sessions, event, now)` маппит событие хука в карточку сессии (статус, задача, текущая активность, `createdAt` - момент первого события для «возраста», `waitingSince` - момент входа в ожидание, `worktree` - имя git-копии, если сессия живёт в `.claude/worktrees/<имя>`, `processPid` - PID процесса агента из заголовка `X-Fleet-Pid`, `activity`/`activityMinute` - искра активности); `pruneStale(sessions, now, staleMs, blankMs)` отсекает протухшие карточки. `unwrapPrompt` снимает XML-обёртки `<cross-session-message>` и `<channel>`: промпт от соседней сессии или с борда это настоящая задача, а не служебная инъекция, и в заголовке должна быть видна сама инструкция. Никаких side effects - тут вся логика, которую покрываем тестами.
- `public/js/lib/activity.js` - **искра активности, общий код сервера и борда**: `bumpActivity` считает события по последним десяти минутам в кольцевом буфере фиксированной длины (`ACTIVITY_BARS`), `sparkBars` досдвигает столбики к текущей минуте на клиенте. Лежит в `public/js/lib`, потому что импортируется и из `state.js` (реэкспорт оттуда для тестов), и из `board-view.js`: один источник, без DOM и без IO. Память не растёт ни от долгой сессии, ни от шторма событий - буфер ограничен по построению.
- `public/index.html` - семантический HTML-каркас борда без встроенных стилей и логики: шапка, рейл под ней, `main` с бордом.
- `public/assets/styles.css` - вся визуальная система: одна тёмная тема (светлой намеренно нет), `@font-face` на локальные шрифты, шапка и рейл, subgrid-таблица строк, карточки и адаптив.
- `public/assets/fonts/` - шрифты файлами, а не с Google Fonts: борд не должен ходить наружу даже за CSS. Roboto Condensed (акценты и цифры, у Barlow из макета нет кириллицы), IBM Plex Sans (текст), JetBrains Mono (id и часы); subsets latin + cyrillic, 12 woff2 на 334 КБ, отдаются с immutable-кэшем.
- `public/js/app.js` - прикладная точка сборки: связывает транспорт, представление,
  рейл, уведомления и пользовательские действия (фокус, удаление, вердикт по разрешению,
  ответ в сессию), не содержит рендеринга и HTTP-деталей.
- `public/js/data/fleet-api.js` - транспортный слой: SSE и HTTP-команды борда, включая
  `sendPermission`/`sendReply` для канала.
- `public/js/board-config.js` и `public/js/lib/format.js` - метаданные статусов, `sectionOf`
  (в какую секцию идёт карточка: `attn` / `done` / `busy`) и чистые форматтеры, не зависящие
  от DOM (`ageText` для колонки возраста, `timerText` для крупного таймера ожидания `м:сс`,
  после часа `ч:мм:сс`).
- `public/js/ui/rail.js` - **рейл гавани** под шапкой: одна ось времени на последние шесть часов, на ней засечки стартов сессий в оттенке проекта, красные засечки входа в ожидание, латунная полоса окна лимита с подписями «окно лимита с 14:30» и «сброс в 19:30 · через 2 ч 05 мин» и маркер «сейчас». Правый край оси это конец окна лимита (или ближайшие полчаса, если окна нет), поэтому «сколько до сброса» читается и как расстояние, и как подпись. Скрыт, пока нет ни сессий, ни окна.
- `public/js/ui/` - слой представления: точечный рендер борда, рейл, favicon, системные
  уведомления и toast. Фон это один радиальный градиент в `.bg` (пятна, сетка и зерно
  прежней версии убраны), сонар-логомарк краснеет при «ждут тебя».

  **Две формы, а не одна.** Ждущая или закончившая ход сессия это карточка (`.card`, у закончившей дополнительно класс `done`), работающая - плотная строка (`.row`); общий класс `.unit` держит цвет статусной полоски и поведение (клик, клавиатура, протухание, кнопка удаления). Секции три: «Ждут тебя» (красные карточки), «Закончили ход» (нейтральные карточки той же формы), «В работе» (строки); у каждой один слот, переезд карточки между двумя карточными секциями элемент не пересоздаёт. Так сделано потому, что вес на борде должен идти за требованием действия: раньше обе секции рисовались карточками, ждущая карточка растягивалась сеткой в 5 колонок и оказывалась **мельче** рабочих - приоритет был инвертирован. Теперь секция "ждут тебя" это карточки до 600px (`repeat(auto-fill, minmax(460px, 600px))`, `justify-content: start`) с крупным таймером ожидания 44px справа, как задержка на табло, а "в работе" - строки высотой ~48px. Потолок дорожки именно 600, а не больше: `auto-fill` считает число колонок по **максимуму** дорожки, и при 640 на мониторе 1900px влезало бы две карточки вместо трёх.

  **Колонки строк задаёт контейнер, строки берут их через `subgrid`.** Секция «в работе» это одна сетка `.tbl` (`224px minmax(0, 1fr) fit-content(420px) 60px max-content max-content max-content 40px`), а каждая `.row` - `grid-template-columns: subgrid`. Так `max-content`-колонки бейджа, возраста и происхождения меряются по всей секции, а не по своей строке, и статусы читаются столбцом, не вчитываясь; тянется только колонка задачи. Пустые ячейки всё равно выводятся, без них сетка съезжает. Адаптив на узких экранах убирает колонки из `.tbl`, строки подстраиваются сами.

  **Группировка без заголовков.** Строки отсортированы проект → агент → старшая сессия выше (`rowOrder`, по `createdAt`: порядок по UUID был случайным и менялся с каждой новой сессией). Первая строка проекта несёт монограмму и имя, следующие получают класс `cont` - уголок продолжения вместо монограммы и приглушённое имя. Отдельного заголовка группы нет: он съедал строку на каждый проект, а при одной сессии в проекте дублировал её же.

  **Голого цветного маркера у проекта быть не должно.** WebStorm и Alacritty уже красят окружение своими цветами, и второй такой же язык цвета на борде спорит с ними. Вместо точки стоит монограмма-аватар `projectMark()`: инициалы (режем и по разделителям, и по камелкейсу: `claude-fleet` → CF, `LearningMy` → LM) плюс приглушённый оттенок. Оттенок выводится из имени папки, а не из порядка в списке, иначе знак проекта менялся бы при появлении сессии в соседнем проекте и глаз перестал бы его запоминать. Тот же оттенок у засечки старта на рейле. Агент (Claude / Codex) подписан монохромно рядом с меткой терминала: своего цвета у него нет, цвет значит либо проект, либо «нужен ты».

  **Движение на борде значит «нужен ты».** Анимации остались только у красного ожидания: `breathe` у красной карточки (у карточки «закончил ход» слоя `.glow` нет вовсе), `ping` у заголовка секции и сонар логомарки (`.mark.alert`, без класса кольца просто не анимируются). У активных строк полоска статична: бегущий градиент был постоянной вознёй на периферии зрения, которая ничего не сообщала. Искра активности не анимируется: столбики меняют высоту только когда изменился их набор (раз в минуту или на событии). Точка `live` тоже статична - см. «Цена анимации» ниже. Новую бесконечную анимацию вне ожидания не добавлять.

  **Цена анимации известна, не гадать.** Борд стоит открытым сутками на втором мониторе, поэтому кадр стоит денег: замерено на стенде (отдельный профиль Chrome, свой GPU-процесс, `--disable-backgrounding-occluded-windows`, иначе macOS глушит отрисовку перекрытого окна и замер врёт). Было 45% ядра в покое и 56% при ждущей карточке, стало 5% и 15%; 5% это floor - ровно столько ест пустая вкладка `about:blank`, то есть в покое борд не стоит ничего сверх самого браузера. Цена посекундного обновления искры (до 10 style-записей на строку при смене столбиков) не замерена.

  Виноваты были не «тяжёлые эффекты», а анимация неправильных свойств. **Анимировать только `transform` и `opacity`** (композит, GPU) и никогда `box-shadow`, `background`, `border-color`, `filter` (перерисовка каждый кадр):
  - дрейф пятен через `transform` со `scale()` заставлял пересчитывать `blur(95px)` на трёх слоях по 50vw каждый кадр - 54% ядра круглосуточно ради текстуры. Сначала пятна сделали статичными, в редизайне убрали совсем: фон это один градиент без blur;
  - `breathe` пульсировал `box-shadow` по периметру карточки шириной 600px - 21% ядра на одну карточку. Свечение вынесено в отдельный слой `.glow`, анимируется его `opacity`; тень внутренняя, потому что `.card` обрезает содержимое (`overflow: hidden`);
  - `ping` и `livePulse` пульсировали спред `box-shadow` у точек 7-8px. Размер не спасает: `ping` стоил 13%. Кольцо переведено на псевдоэлемент с `transform: scale`, у `live` пульсация убрана совсем - связь читается цветом;
  - `backdrop-filter` шапки пересчитывался каждый кадр, потому что под ним двигались пятна. Заменён непрозрачным фоном;
  - сонару добавлен `will-change: transform, opacity`: без своего слоя обводка с `border-radius` рерастеризовывалась при масштабировании (10%).

  Мерить цену анимации «на глаз» по одному прогону нельзя вдвойне: пока `breathe` и сонар были дорогими, `ping` в замере выглядел бесплатным и проявился только после их починки.

  Фон и поверхности идут лесенкой (`--bg` → `--surface` строки → `--surface-2` карточки). Борд дважды уезжал в слишком тёмное; видимый фон задаёт **радиальный градиент в `.bg` поверх `body`**, поэтому осветлять надо именно его внешний цвет - он занимает низ и края экрана, а `--bg` почти не виден.

  Многоточие в чипе инструмента висит на внутреннем `.tt`, а не на `.tool`: `text-overflow` не действует на flex-контейнер, и длинная команда обрубалась ровно по букве, выглядя как баг рендера.

  **Окно лимита живёт на рейле, а не в карточке и не в шапке.** Лимит у аккаунта общий, в каждой строке это было бы одно и то же число, а плашка в шапке (прежняя `.win`) показывала только цифру без контекста. На рейле окно это латунная полоса на той же оси, где стоят старты сессий и маркер «сейчас»: видно и когда началось, и сколько осталось, и что было в этом окне. После истечения - подпись «лимит Claude свежий · счётчик пойдёт со следующего запроса». Цвет латунный, не красный: красное на борде означает «нужен ты», а окно это справка. Сервер шлёт только границы (`usage.startedAt`/`endsAt`), обратный отсчёт двигает `rail.tick` в общем секундном тике; подписи лежат в `data-label`/`data-start` и рисуются через `attr()`, а тик переписывает их только когда текст реально изменился. Ось перестраивается целиком лишь когда сдвинулся её левый край (`paintedLeft`) или в снимке изменились сами засечки либо границы окна (`railSig`): остальные поля карточек меняются на каждом событии хука, и пока рейл перестраивался на любой снимок, он делал полный `innerHTML` несколько раз в секунду рядом с точечно рисуемым бордом.

  Когда ждущих нет, но сессии есть, на месте красной секции показывается спокойная плашка `.calm` («Никто не ждёт»). Без неё спокойный борд выглядел ровно так же, как борд, на который просто не с той стороны посмотрели.

  Масштаб рассчитан на взгляд с расстояния - борд живёт на втором мониторе, а не под носом: базовый шрифт 15px, текст «чего ждут» на карточке 17px, таймер ожидания 44px, заголовок секции 22px, задача в строке 15px, строка ~48px высотой. Мельчить нельзя, даже если «влезает больше»: борд уже один раз уезжал в слишком мелкое. Карточка и строка это `div[role=button]`, а не `<button>`: внутрь вложены кнопка удаления и (с каналом) кнопки вердикта и форма ответа, а кнопку в кнопку нельзя - поэтому Enter/Space обрабатываются вручную (`keydown` на `board`), иначе борд перестал бы работать с клавиатуры; клик и Enter внутри `.kill`, `.acts`, `.reply` к сессии не ведут. Метка терминала - брендовым цветом маркера (`termColor` / `TERM_COLORS`).

  Рендер точечный: элемент создаётся один раз на сессию (реестр `cardEls`) и дальше только переставляется и обновляется внутри по своей сигнатуре; у каждой секции один слот, порядок внутри задаёт сам `append` (существующий элемент переезжает, не создаётся), скелет секций перестраивается, только когда меняется сама раскладка (`lastLayout`). Так `:hover` не гаснет под курсором (а кнопка удаления показывается именно по ховеру), не сбрасывается фокус клавиатуры и клик не промахивается. Единственный случай пересоздания элемента - смена формы (`entry.shape`), когда сессия переезжает между секциями: внутри строки иначе остался бы markup карточки. Исчезнувшие сессии выкидываются из реестра (`forgetGoneCards`), иначе он растёт до перезагрузки страницы. Раз в секунду `tickTimes` двигает таймер/возраст на месте, подсвечивает протухшие и досдвигает искру; всё, что тикает без ре-рендера, лежит на самом элементе (`syncLive`: `dataset.ts`, `dataset.act`, `dataset.actmin`), потому что у строки нет подписи «N сек назад», а искра не должна ждать следующего события, чтобы погаснуть. Динамический favicon рисуется на canvas: краснеет и показывает число, когда кто-то ждёт (сигнал на иконке фоновой вкладки).
- `hooks/report.sh` - неблокирующий форвардер: пробрасывает stdin (JSON события) в `/event`. Сам находит свою папку (`BASH_SOURCE`), порт берёт из `.env`. Короткий таймаут, всегда `exit 0`.
- `scripts/board.sh` - открывает борд отдельным окном-приложением Яндекс Браузера (`--app=<url>`). Годится и для рук, и для автозапуска при логине: ждёт сервер до 20 сек (`FLEET_BOARD_WAIT`) и не поднимает второе окно поверх уже открытого борда (`--force`, если окно нужно именно новое). Два пути запуска браузера, и это не дублирование: **запущенному** браузеру `--app` отдаёт прямой вызов бинаря (процесс сразу выходит; через `open -na` нельзя - `-n` поднял бы второй экземпляр со своим профилем), а **холодный** старт идёт через `open -b ru.yandex.desktop.yandex-browser --args` (см. инвариант ниже). Если Яндекса нет - фолбэк на браузер по умолчанию.
- `test/state.test.js`, `test/focus.test.js`, `test/guards.test.js`, `test/usage.test.js`, `test/liveness.test.js`, `test/client-format.test.js`, `test/board-config.test.js` - `node --test`, покрывают пять чистых ядер, форматтеры борда и раскладку карточек по секциям.
- `test/server.test.js` - тесты маршрутов на настоящем процессе: поднимает `server.js` спавном на свободном порту со своим `FLEET_STATE_FILE`, пустой папкой транскриптов и `FLEET_CHANNEL=1`. Ловит то, что живёт только в склейке: падение процесса на битом id, буфер SSE у нечитающего клиента, коалесинг рассылки, защиту маршрутов канала, права персиста, лог конфига. Живой борд и его `.fleet-state.json` не трогает.
- `test/helpers/fleet-process.js` - спавн `server.js` для тестов на настоящем процессе (`startServer`, `subscribe`, `snapshot` первого кадра `/stream`). Лежит под `test/`, поэтому `node --test` считает его за один проходящий тест без проверок: в итоге summary на единицу больше числа настоящих тестов.
- `test/channel.e2e.test.js` - сквозной прогон канала ответа: настоящий `server.js` плюс настоящий `channel/fleet-channel.js`, с которым тест играет Claude Code по stdio (`initialize` с capability, `permission_request` до карточки, вердикт и текст в stdout, выход по закрытию stdin). Канал привязывается к карточке по `process.ppid`, то есть по PID процесса теста. Без SDK в `channel/node_modules` тест пропускается (`skip`), в CI его гоняет отдельный job.
- `scripts/install.sh` / `scripts/uninstall.sh` - установка и снятие: `.env`, хуки в `~/.claude/settings.json` (мерж через node, с бэкапом, чужие хуки не трогаются), plist из текущего пути репозитория и абсолютного пути node, перезагрузка агентов. Агентов два: сервер и (при `FLEET_AUTOOPEN=1`) `<label>-board`, разовый `RunAtLoad` без `KeepAlive`, который при логине зовёт `board.sh`. Выключение автозапуска ранее поставленный агент снимает, `uninstall.sh` гасит оба. Идемпотентно, гоняется повторно после переезда папки или обновления node.
- `.env` / `.env.example` - конфиг (реальный `.env` в `.gitignore`, шаблон закоммичен).

## Конфиг (`.env`)

Машинно-зависимые литералы и настройки живут в `.env`, не в коде. Node 22 читает файл сам.

| Переменная | Дефолт | Что |
|------------|--------|-----|
| `FLEET_PORT` | `4319` | порт сервера; его же читает `report.sh` (единый порт) |
| `FLEET_HOST` | `127.0.0.1` | хост привязки, только localhost |
| `FLEET_ALLOWED_HOSTS` | пусто | доп. значения заголовка `Host` через запятую (смотреть борд с планшета). Пусто = только localhost |
| `FLEET_STALE_HOURS` | `6` | порог простоя карточки: и при восстановлении с диска, и для рантайм-уборки зомби (`pruneStale` раз в 5 мин) |
| `FLEET_BLANK_MINUTES` | `15` | тот же порог, но для пустой карточки (ни задачи, ни инструмента): фоновый агент, остаток от перехода в worktree, брошенная сессия |
| `FLEET_TRANSCRIPTS` | `~/.claude/projects` | папка транскриптов Claude Code, по ним считается окно лимита (только чтение) |
| `FLEET_USAGE_HOURS` | `5` | длина окна лимита; не наша настройка, а свойство тарифа - поменяют, поправишь одну строку |
| `FLEET_USAGE_ALIGN_MIN` | `30` | до какой границы округляется вниз старт окна (0 - не округлять) |
| `FLEET_WEBSTORM` | `/usr/local/bin/webstorm` | путь к CLI-лаунчеру WebStorm (на разных машинах разный) |
| `FLEET_WEBSTORM_APP` | `WebStorm` | имя приложения для фолбэка `open -a` |
| `FLEET_AUTOOPEN` | `1` | ставить ли агент автооткрытия борда при логине; читает только `install.sh` |
| `FLEET_BOARD_WAIT` | `20` в скрипте, `60` в `.env.example` | сколько секунд `board.sh` ждёт ответа сервера при автозапуске, прежде чем сдаться. Дефолт скрипта 20, но на холодной загрузке системы node/fnm поднимается дольше (в логе бывало 60+ с от boottime), поэтому шаблон конфига ставит 60 |
| `FLEET_CHANNEL` | `0` | прототип ответа с борда: `1` включает маршруты `/channel/*` и поля `channel`/`permission` в снимке. Сам процесс канала подключает владелец через `claude mcp add` (см. `install.md`, «Ответ с борда») |
| `FLEET_STATE_FILE` | `.fleet-state.json` в корне | путь персиста. Нужен тестам маршрутов, которые поднимают настоящий `server.js` и не должны затирать состояние живого борда; в `.env` обычно не задаётся |

Числовые переменные читает `envNumber()`: не задана - дефолт молча, задана мусором или нулём - дефолт со строкой в `fleet.log`. Раньше `Number(x) || 6` превращал `FLEET_STALE_HOURS=0` в шесть часов без единого следа. Уже заданные переменные окружения `.env` не перебивает (так работает `process.loadEnvFile`), на этом держатся тесты.

## Ключевые инварианты (не ломать)

- **`report.sh` обязан быть безопасным для чужих сессий**: `exit 0` всегда, пустой stdout, микро-таймаут. Он висит глобально на каждом вызове тула во всех проектах - любая его ошибка/задержка/вывод ударит по всем сессиям Claude Code. Не добавлять сюда логику, только форвардинг.
- **`state.js` держать чистым** (без IO, без Date.now внутри - время приходит параметром). Вся новая логика карточек - сюда, с тестом.
- **Машинно-зависимые пути/настройки - в `.env`, не литералами в коде.** Путь к WebStorm, порт, хост и т.п. читаем из env с дефолтами.
- **Никаких внешних зависимостей** без явной причины. Тулза должна стартовать мгновенно и есть ~30-60 МБ, не больше. Никакого Electron, никакого bundler.
- **Только localhost, и `Host` проверяем.** Сервер биндится на `FLEET_HOST` (дефолт `127.0.0.1`), но одной привязки мало: при DNS rebinding страница злого сайта резолвит свой домен в `127.0.0.1` и становится same-origin с бордом, после чего читает `/stream` - а там все промпты, пути проектов и команды Bash. Поэтому `isAllowedHost()` пускает только localhost-хосты (плюс `FLEET_ALLOWED_HOSTS`), а `isCrossSite()` рубит мутирующие запросы с чужой страницы по `Sec-Fetch-Site`/`Origin`. `report.sh` ходит через curl - у него этих заголовков нет, он проходит. Проверки снимать нельзя.
  **Мутирующим считается и GET `/channel/commands`** (`mutating` в `route()`): он регистрирует канал и рвёт прежний. Пока проверка стояла только на не-GET, чужая страница одним `fetch` перехватывала канал настоящей сессии, а 64 таких запроса забивали реестр до 503 для всех новых сессий (воспроизведено на копии). Процесс канала Origin не шлёт и проходит. Новый GET с побочным эффектом обязан попадать в `mutating`.
  **Список Origin выводится из того же списка хостов** (`buildAllowLists` в `guards.js`), а не задаётся отдельно. Пока Origin был захардкожен на localhost, борд с планшета через `FLEET_ALLOWED_HOSTS` открывался на просмотр, но клик по карточке и удаление ловили 403: `isCrossSite` не узнавал собственную же страницу. Добавляешь способ обратиться к борду - добавляй и Host, и Origin, иначе фича будет работать наполовину.
- **Тело события ограничено** (`MAX_BODY` 4 МБ, жёсткий предел 32 МБ): в `tool_response` может лежать содержимое большого файла. Четыре, а не один: в `fleet.log` 03.09 два `PostToolUse` по 1.0 и 1.3 МБ были отброшены, и карточка залипла на прошлом статусе до следующего тула. Сверх лимита в память не копим, но поток дочитываем - оборвать сокет значит лишить отправителя внятного ответа. Отброс пишется в лог, иначе карточка молча залипнет на прошлом статусе.
- **Ответ с борда - прототип за флагом `FLEET_CHANNEL=1`, без флага борд прежний.** Маршруты `/channel/*` не поднимаются, снимок не несёт полей `channel`/`permission`, кнопки и форма ответа на карточке рисуются только при `c.channel` - кнопки-обманки хуже их отсутствия. Механика: Claude Code сам запускает `channel/fleet-channel.js` на сессию (MCP-сервер по stdio, research preview каналов), тот держит SSE к борду; текст с борда уходит в сессию как `notifications/claude/channel` с `meta.origin=board`, вердикт по разрешению - как `notifications/claude/channel/permission`. Терминальный диалог разрешения при этом остаётся открытым, применяется первый ответ: 409 с борда значит «уже ответили в терминале», не ошибка. Карточка и канал находят друг друга по PID процесса `claude` (`processPid` карточки = `process.ppid` канала), общего id у них нет. Всё тяжёлое (SDK, zod) живёт в `channel/` со своим `package.json`; сервер борда остаётся без зависимостей. Проверено сквозным прогоном на копии: initialize с capability, `/stats.channels=1`, permission_request доходит до карточки, вердикт уходит в stdout, текст уходит уведомлением, чужой Origin ловит 403, закрытие stdin завершает процесс за миллисекунды. **Не проверено с настоящим Claude Code**: флаг `--dangerously-load-development-channels`, диалог согласия на MCP-сервер, что `ppid` процесса канала это PID `claude`, поведение при открытом AskUserQuestion.
- **Рассылка SSE не копит память под нечитающего клиента и не шлёт снимок на каждое событие.** Вкладка на уснувшем планшете или half-open TCP перестаёт читать, а `res.write` при этом не падает, а складывает данные в буфер процесса: замерено, 6000 событий при снимке 15 КБ дали +203 МБ RSS, и после разрыва память не вернулась. Поэтому все записи идут через `writeSse()`: буфер больше `SSE_MAX_BUFFERED` (1 МБ) значит «клиент мёртв», сокет рвём, `EventSource` переподключится сам; на сокетах включён TCP keepalive. Вторая половина: `broadcast()` не шлёт сразу, а ставит таймер на `BROADCAST_DEBOUNCE_MS` (50 мс), потому что снимок это всё состояние целиком и шторм событий давал 20 КБ на событие в каждый борд (123 МБ за 6000 событий). Прямая запись `res.write` в SSE-поток в новом коде недопустима.
- **Маршрут не роняет процесс.** Один `POST /focus/%` убивал сервер: `decodeURIComponent` кидал `URIError` сквозь `http.createServer`, обработчика `uncaughtException` нет, launchd поднимал процесс через `ThrottleInterval` 30 с, и всё это время борды и каналы были без связи, а события хуков молча терялись. Теперь id из пути берёт `decodeId()` (битый id это 400), `route()` обёрнут в try/catch (500 одному запросу плюс стек в лог), а ошибки асинхронных обработчиков пишет `guard()`, а не глотает `.catch(() => {})`. Тест на это в `test/server.test.js`.
- **Персист пишется с правами 0600.** В `.fleet-state.json` лежат промпты и команды Bash всех сессий; `writeFileSync` временного файла получает `mode: 0o600`, а `rename` переносит права на целевой файл.
- **Уведомления не навязываются.** Выключены по умолчанию, состояние в `localStorage`, всегда `silent: true`, только про новые ожидающие сессии, один общий `tag` (новое заменяет старое, а не копится). Первый снапшот после открытия борда уведомлений не даёт - это текущее положение дел, а не события. Борд задумывался как тихий сигнал, и таким должен остаться по умолчанию.
- **Включение колокольчика шлёт пробное уведомление.** Не украшение: настоящие приходят только когда сессия входит в ожидание, то есть неизвестно когда, и до тех пор непонятно, работают они вообще или нет. Вторая причина важнее - на macOS браузер попадает в системный список «Уведомления» только после того, как отправит первое; пока он ничего не отправлял, разрешить ему там нечего (проверено: разрешение в самом браузере для `localhost:4319` стояло, а в `com.apple.ncprefs` браузера не было вовсе, и уведомления не появлялись). Пробное уведомление заставляет macOS показать свой диалог. Всё создание уведомлений идёт через одну функцию `postNotification`.
- **Ничто в памяти не растёт без предела.** Проверено нагрузкой: 40 000 событий и 300 подключений борда дают плато (60 → ~70 МБ в реальном темпе, ~105 МБ под штормом в 12 тыс. соб/с), утечек нет. Оба счётчика событий - `unknownEvents` и разбивка `stats.byEvent` для `/stats` - ограничены по числу ключей через `boundedKey()` (`MAX_UNKNOWN_KINDS` и `MAX_EVENT_KINDS`), лишние имена сваливаются в строку «прочие». Без ограничения поток событий с уникальными именами раздувал Map без предела: замерено, 12 000 разных имён давали 82 МБ и рост не останавливался, с ограничением RSS выходит на плато 73 МБ. `stats.byEvent` был пропущен при первой правке именно потому, что выглядел безобидной диагностикой - любую новую накапливающую структуру ограничивать сразу, даже если она «просто для счётчиков».
- **Старт окна лимита выравнивается вниз до получаса.** Claude открывает окно не по секунде первого запроса, а по ближайшей границе получаса. Сверено с экраном `/usage`: первая активность дня в 09:32:40, первый ответ в 09:34, официальный сброс в 19:30 - то есть цепочка 09:30 → 14:30 → 19:30, а без выравнивания борд показывал 19:34. Округление живёт в `foldStamps` (при открытии окна), а не в показе: от округлённого старта считается граница следующего окна, иначе метка сразу после сброса попала бы в уже закрытое окно и расхождение копилось бы с каждым блоком. Если борд начнёт расходиться с `/usage` - сначала сверить именно эту границу, а не искать потерянные события.
- **Чтение транскриптов идёт в один буфер на процесс.** Свежие транскрипты за десять часов весят под 50 МБ, и наивные подходы к их разбору бьют по памяти втрое сильнее, чем кажется. Замерено снаружи (`ps`, без опроса `/stats` - опрос сам искажает картину): пик RSS при `Buffer` на весь остаток файла 96 МБ, при чтении потоком с `encoding: 'utf8'` 133 МБ (поток аллоцирует новый буфер на каждый кусок, и мусор копится быстрее, чем работает GC), при чтении в переиспользуемый `READ_BUFFER` 69 МБ против 61 МБ у версии без фичи. Декодируем только саму дату, а маркеры ищем буферным `indexOf` - нужного текста в транскрипте меньше процента. Читать файлы «умнее» (хвостом с ранней остановкой на старых записях) смысла нет: замерено, 48 МБ из 65 и так относятся к последним десяти часам.
- **Транскрипты читаются, только пока борд открыт.** Без единого SSE-клиента `scanUsage` не запускается вовсе: борд стоит открытым сутками, но когда его закрыли, процесс обязан стоять на нуле. При подключении первого клиента скан идёт сразу, дальше раз в минуту - чаще незачем, обратный отсчёт тикает на фронте сам.
- **Незнакомые события хука считаем и показываем.** Схема событий Claude Code не наша: обновится - и часть статусов молча перестанет обновляться. `isHandledEvent()` в `state.js`, счётчик в `server.js`, янтарный бейдж в шапке борда.
- **Цена события известна, не гадать.** Замерено на живой работе через `/stats`: `PostToolUse` в среднем 20 КБ и до 54 КБ (в `tool_response` лежит результат инструмента), `PreToolUse` - 2.9 КБ. То есть тяжелее в разы, но до лимита `MAX_BODY` (4 МБ) запас в 80 раз, и по loopback такие тела уходят за миллисекунды - `--max-time 0.5` в `report.sh` им не помеха. Если появится подозрение на потерянные события, первым делом смотреть `/stats`, а не догадки.
- **`report.sh` не должен форкать процессы.** Порт из `.env` читается циклом `while read` на чистом bash, путь - через `${BASH_SOURCE[0]%/*}`. Прежние `$(cd .. && pwd)` и `grep|tail|cut|tr` стоили 5 форков на каждый вызов инструмента: 18.5 мс против нынешних 13 мс.
- **Персист пишется атомарно** (`.tmp` + `renameSync`): падение в момент записи иначе оставит обрезанный JSON, а `loadState` молча вернёт `{}` и все живые карточки исчезнут.
- **Персист (`.fleet-state.json`) - страховка, не история.** Переживает рестарт сервера, но при ребуте сбрасывается (сравнение mtime файла с временем загрузки через `os.uptime()`). Не превращать в лог завершённых сессий.
- **Зомби-карточки чистятся в рантайме.** `SessionEnd` приходит только на аккуратный `/exit`; при закрытии окна терминала / kill / крэше его нет. Поэтому таймер в `server.js` раз в 5 мин прогоняет `pruneStale` с порогом `STALE_MS` (тот же `FLEET_STALE_HOURS`) и вещает изменения. Логику «что протухло» держим в `state.js` (чистая функция), сам таймер - в `server.js`.
- **Закрытая сессия исчезает по PID за 10–20 секунд, а не через часы.** `SessionEnd` приходит только на аккуратный выход: Claude молчит при закрытии окна терминала, kill или крэше, Codex по контракту шлёт его лишь через 30 минут без подключённых клиентов. PID процесса агента приходит из `$PPID` hook-команды заголовком `X-Fleet-Pid` и хранится в `processPid` для любого агента: у Codex IDE запускает отдельный процесс на сессию, у Claude `$PPID` хука это сам процесс `claude` (проверено выборкой `ps`: процессы `bash` хука с PPID = PID `claude`). `server.js` раз в 10 секунд (и только при открытом борде) проверяет PID через `process.kill(pid, 0)`, а `pruneClosedSessions` в `liveness.js` требует два промаха подряд, поэтому краткое переподключение карточку не удаляет. Старые карточки из персиста без `processPid` этой уборке не подлежат - для них остаётся `pruneStale` и кнопка ×. Вариант с `lsof` отклонён после замера: 200 запусков заняли 14.81 с CPU, то есть опрос раз в 10 секунд съедал бы около 0.74% одного ядра.
- **Пустая карточка живёт минуты, а не часы.** Карточка без задачи и без инструмента (`isBlank`) убирается через `BLANK_MS` (`FLEET_BLANK_MINUTES`, 15 мин) - и в рантайме, и при восстановлении с диска. Так выглядит не работа, а мусор: фоновый агент со своим `session_id`, остаток от перехода в worktree, брошенная сессия. Потерять по ней нечего: сказать ей нечего, а на первом же настоящем событии она вернётся. Общий шестичасовой порог для сессий с задачей оставлен как был - там ожидание может быть законным.
- **Сессия в git-worktree принадлежит родительскому проекту.** `.claude/worktrees/<имя>` разбирается в `placeFromCwd`: проект берётся от родителя, имя копии живёт отдельным полем `worktree` и показывается чипом. Иначе каждая изолированная копия заводила на борде собственную группу с собственной монограммой, хотя это та же работа - а таких копий за день бывает несколько.
- **Браузер нельзя запускать из-под launchd прямым вызовом бинаря.** Пока Яндекс уже работает, прямой вызов безобиден: процесс отдаёт `--app` живому браузеру и сразу выходит. Но на холодную он сам становится главным процессом браузера и наследуется тем, кто его позвал: у launchd-агента это значит, что job числится живым всё время жизни браузера, а любой `launchctl bootout` - включая повторный прогон `install.sh` - закрывает Яндекс со всеми вкладками пользователя. Поэтому холодный старт только через `open -b <bundle-id> --args`, плюс `AbandonProcessGroup` в plist как страховка. Проверено: `ppid` поднятого браузера равен 1, а не агенту.
- **Нулю в `boards` верить сразу нельзя.** `install.sh` перезапускает сервер прямо перед стартом агента борда, рестарт рвёт все SSE, и уже открытое окно возвращается в счётчик лишь через пару секунд. Пока `board.sh` читал `/stats` один раз, установка исправно дублировала окно борда. Ноль перепроверяется 6 секунд (`FLEET_BOARD_SETTLE`), непустой ответ принимается сразу. Любая будущая проверка «открыто ли уже» обязана учитывать этот же лаг переподключения.
- Правится только `~/.claude/settings.json` (там хуки). Файл `~/.claude.json` не трогать.

## Что показывает карточка

- **статус** (приблизительно из типа события, точной телеметрии у хуков нет): `ready` (SessionStart) · `thinking` (UserPromptSubmit / PostCompact) · `tool` (PreToolUse) · `working` (PostToolUse) · `error` (PostToolUse с ошибкой, PostToolUseFailure) · `compacting` (PreCompact) · `waiting` (Notification / Stop / StopFailure). `SubagentStop` статус НЕ трогает: заканчивается субагент, а сессия работает дальше - пометить её «закончил ход» значит увести работающую сессию из «в работе».
- **чего именно ждут** - `note`, текст уведомления из `Notification` («Claude needs your permission to use Bash»). Плюс при `permission`/`question` показывается `tool` + `toolInfo`: видно, на что спрашивают разрешение (`Bash · git push --force`), и решение принимается не вставая. Сбрасывается на любом следующем событии.
- **задача** - последний промпт (`title`, из `UserPromptSubmit`). Служебные инъекции (`<task-notification>`, `<system-reminder>`, слэш-команды, bash-проброс) в заголовок не пишутся - фильтр `isServicePrompt` в `state.js`, чтобы не затирать реальную задачу. Промпт в обёртке `<cross-session-message>` или `<channel>` пишется без обёртки (`unwrapPrompt`). Пока промпта не было, строка показывает курсивный плейсхолдер «новая сессия, промпта ещё нет» вместо пустой ячейки.
- **активность "над чем сейчас"** - `tool` + `toolInfo` из `tool_input` (какой файл читает/правит, какую команду в Bash, паттерн Grep, описание субагента у `Agent`, первый вопрос `AskUserQuestion`, имя `Skill`, запрос `ToolSearch` - `toolTarget()` в `state.js`).
- **искра активности** - в строке десять столбиков по минутам (`activity`, сколько событий пришло в каждую из последних десяти минут). Гаснет в серый, когда последние две минуты пусты: затухание видно раньше, чем бейдж «нет активности». Столбики досдвигает клиент по текущей минуте, серверу для этого таймер не нужен.
- **где живёт** - метка терминала (`terminal`) из `appId` (`terminalName()` в `state.js`): WebStorm / Alacritty / iTerm / Terminal / ...
- **в какой копии** - чип `worktree` с пунктирной рамкой (у карточки рядом с именем проекта, у строки перед задачей), если сессия работает в `.claude/worktrees/<имя>`. Пунктир, а не сплошная плашка: сплошная это метка терминала, и два одинаковых чипа рядом читались бы как одно и то же
- **возраст** - «идёт N мин» из `createdAt` (когда карточку впервые увидели), рядом с id. У `waiting` возраст не показываем: время ожидания уже стоит в бейдже, а два времени в узкой карточке съедают имя проекта.
- **сколько ждёт** - у красной карточки крупный таймер 44px справа (`м:сс`, после часа `ч:мм:сс`), тикает в `tickTimes`. Считается от `waitingSince`, а НЕ от `updatedAt`: `updatedAt` двигает любое входящее событие (повторный idle-Notification, `SubagentStop`), и пока время брали оттуда, счётчик обнулялся прямо во время ожидания, а карточка проваливалась вниз секции. Секция «ждут тебя» отсортирована так, что дольше всех ждущий сверху: разбираешь самое залежавшееся, и новая красная карточка не сдвигает те, что уже в списке.
- **ответить с борда** - только при подключённом канале (`c.channel`): на карточке с открытым запросом разрешения кнопки «Разрешить»/«Отказать», на остальных карточках строка ввода «Ответить сессии…», текст уходит в сессию как следующий ход. Подпись «через канал fleet» напоминает, что это прототип, а не штатный путь.
- **убрать руками** - кнопка × в углу карточки (видна на ховере) шлёт `DELETE /session/:id`. Это аварийный выход для карточки из персиста без `processPid` или зомби, у которого PID ещё жив; закрытые сессии с известным PID убираются автоматически за 10–20 секунд.
- **протухание** - активная карточка (`thinking`/`tool`/`working`/`error`/`compacting`) без событий дольше `IDLE_MS` (4 мин) тускнеет и показывает «нет активности»: вероятно сессия подвисла или её закрыли. `waiting`/`ready` не трогаем - они законно ждут человека. Это визуальная подсказка на фронте; окончательно зомби убирает `pruneStale` (см. инварианты).

`waiting` раскладывается по двум секциям по причине (`sectionOf` в `board-config.js`, чистая, с тестом):
- `finished` - Stop, закончил ход. **Своя нейтральная секция «Закончили ход»** между красной и строками: та же форма карточки с таймером («простаивает»), но без красного, без `.glow` и без пинга. Решение владельца от 05.09.2026: закончить ход это не просьба о помощи, сессия просто стоит без промпта, а красное на борде значит только «нужен ты». В счётчик favicon, число в заголовке вкладки, сонар логомарки, уведомления и красную засечку на рейле эти карточки не попадают; в шапке у них свой счётчик «закончили ход».
- `permission` - Notification про разрешение - красное, «ждут тебя»
- `question` - Notification-вопрос/простой/AskUserQuestion - красное
- `failed` - StopFailure, ход оборвался ошибкой API и сессия встала сама - красное
- причина не распознана - красное: лучше позвать зря, чем спрятать

Причина берётся из `notification_type` (`permission_prompt` / `idle_prompt` / `agent_needs_input` /
`elicitation_dialog`), а разбор английского текста `message` оставлен фолбэком
для версий без этого поля. `auth_success` и прочие информационные уведомления статус не трогают:
раньше любой Notification красил карточку в красное и звал к сессии, которой ты не нужен.
`idle_prompt` на уже ждущей карточке игнорируется целиком - это напоминание о простое, а не новая
причина, и раньше оно подменяло «закончил ход» на «нужен ответ».
`agent_completed` тоже информационное, по той же причине, что и `SubagentStop`: закончился фоновый
агент, а сессия работает дальше. Причём у фонового агента **свой `session_id`**, и уведомление
приходит не в родительскую карточку, а в собственную - пустую, без промпта и без терминала.
Пока оно значило «закончил ход», такая карточка навсегда зависала красной в «ждут тебя».

## Запуск и тесты

```bash
./scripts/install.sh   # конфиг + хуки + launchd-агент, идемпотентно
node server.js         # или npm start, если хочется руками
node --test            # или npm test
npm run verify:liveness # 1 млн PID-check + 1 млн churn/GC, бюджеты CPU/RAM и утечки
./scripts/board.sh     # открыть борд окном-приложением Яндекс Браузера (--force для второго окна)
./scripts/uninstall.sh # снять агент и свои хуки
```

Автозапуск - launchd-агент `com.rasulkiller.claude-fleet` (см. `install.md`). Логи - `fleet.log`
и `fleet.error.log`. Агент перезапускается только после падения (`KeepAlive` = `Crashed`),
поэтому остановленный вручную остаётся остановленным.

CI (`.github/workflows/ci.yml`) идёт параллельными job: `syntax` (`node --check` по всем js/mjs
из `git ls-files`, `bash -n` по sh), `unit` (`node --test` на Node 22 и 24, e2e канала там
пропускается без SDK), `liveness` (`verify:liveness`, локально 1.1 с) и `channel` (`npm ci` в
`channel/`, затем `test/channel.e2e.test.js`). Job канала гоняется всегда, а не только по
`paths: channel/**`: e2e проверяет и маршруты `/channel/*` в `server.js`, и фильтр по путям
молчал бы ровно на тех правках сервера, где он нужнее всего. Новый пуш в ту же ветку снимает
прежний прогон (`concurrency` с `cancel-in-progress`).

## После изменений

- Тронул `state.js`, `focus.js`, `guards.js`, `usage.js`, `liveness.js` или `public/js/lib/activity.js` - прогони `node --test`, добавь/поправь тест на новое поведение. Для liveness дополнительно `npm run verify:liveness`: он проверяет миллион PID-проб, миллион циклов смены карточек, пустой bounded `Map` и плато памяти после прогрева V8.
- Тронул `channel/fleet-channel.js` или маршруты `/channel/*` - `node --test test/channel.e2e.test.js`: он и есть сквозной прогон (MCP-клиент по stdio с `initialize` и `notifications/initialized`, `/stats.channels`, `permission_request`, вердикт, текст, закрытие stdin и выход процесса). Нужен установленный SDK: `npm ci --prefix channel`. Живой `~/.claude.json` (`claude mcp add`) не трогать - это правка за владельцем.
- Тронул `scripts/install.sh` - проверяй на фейковом `HOME` и своём `FLEET_LABEL` с нерабочим портом в `.env`, а не на живой системе. Обязательно клади в тестовый `settings.json` чужой хук: он должен пережить и установку, и удаление. Копию репозитория для проверки клади в путь с пробелом: команда хука пишется в кавычках (Claude Code запускает её через shell), а старую голую форму из прежних установок скрипт переписывает на месте, не дублируя; `uninstall.sh` узнаёт обе формы. Нерабочий порт бери привилегированный (`FLEET_PORT=1`): на свободном высоком порту копия сервера реально поднимется и агент борда откроет лишнее окно.
- Тронул `scripts/board.sh` - гоняй все три пути: холодный старт (браузер закрыт), горячий (`--force` при живом браузере) и защиту от дубля. Лишние окна закрывать за собой: `osascript -e 'tell application "Yandex" to close window 1'`.
- Тронул `server.js` - прогони `node --test` (маршруты покрывает `test/server.test.js` на настоящем процессе), затем перезапусти процесс: `launchctl kickstart -k gui/$(id -u)/com.rasulkiller.claude-fleet`, проверь борд вживую.
- Тронул `com...plist` (или env в нём) - нужен полный reload: `launchctl bootout ...` + `launchctl bootstrap ...` (kickstart плист не перечитывает).
- Тронул что-либо в `public/` - сервер отдаёт клиентские файлы с `Cache-Control: no-cache`, достаточно обновить вкладку браузера (Cmd+R). Визуально проверять через headless Chrome на изолированной копии с другим портом - живой сервер и `.fleet-state.json` не трогать.
- Тронул код - обнови `CLAUDE.md` в той же сессии, чтобы дока не расходилась с реализацией (проверяй карту файлов, инварианты, «что показывает карточка»).
- Правило проекта: сначала переименование/выделение метода ради читаемости, комментарий только на "почему".
- **Синтетические события слать только в изолированную копию.** POST в живой `/event` с придуманным `session_id`/`cwd` создаёт настоящую карточку (был случай: замер производительности с `cwd=/tmp` нарисовал на борде проект `tmp`). Для проверок - копия в scratchpad со своим портом, живой борд не трогать.
- Процесс копии убивать по порту (`lsof -ti :4399 | xargs kill`), а не через `pkill -f <путь>`: запущенный как `node server.js` он в списке процессов без полного пути, `pkill` его не находит, и дальше тесты бьют в старую версию.
