# claude-fleet

Локальный дашборд статусов всех сессий Claude Code. В одном окне видно: какая сессия
работает и над чем, какая ждёт твоего вмешательства, какая закончила ход. Цель - убрать
поллинг по вкладкам терминала. Работа идёт строго в WebStorm, тулза этого не меняет:
хуки пассивные, интерактивные сессии в табах остаются как есть.

Пользовательская дока - `README.md`, установка - `install.md`. Этот файл - для работы
над самим кодом.

## Как устроено (поток данных)

```
сессия Claude ──(hook)──> hooks/report.sh ──POST /event──> server.js ──SSE /stream──> public/index.html
клик по карточке ──POST /focus/:id──> server.js ──> проект в WebStorm (если .idea + WebStorm-терминал)
                                                     иначе: open -b <bundle-id терминала сессии>
```

Сессия живёт не обязательно в WebStorm (может быть Alacritty/iTerm/Terminal, напр. `claude`
из home). `report.sh` шлёт bundle-id терминала (`__CFBundleIdentifier`) заголовком `X-Fleet-App`,
и клик возвращает туда, где сессия реально запущена - `resolveFocus()` в `server.js`.

Состояние держится в памяти и локально персистится в `.fleet-state.json` (переживает
рестарт сервера; при ребуте системы сбрасывается по времени загрузки). Наружу с машины
ничего не уходит. Звука нет намеренно - сигнал это сам борд плюс красный favicon-бейдж со
счётчиком и число в заголовке вкладки (видно на фоновой вкладке). Системные уведомления
существуют, но выключены по умолчанию и всегда беззвучные: они для случая, когда борда не
видно вообще (фуллскрин IDE).

## Карта файлов

- `server.js` - `node:http` сервер: SSE `/stream`, приём событий `/event`, `/focus/:id` (фокус WebStorm), `DELETE /session/:id` (убрать карточку руками), `GET /stats` (диагностика: аптайм, RSS, процессорное время, число сессий и открытых бордов, размеры событий по типам), персист состояния. Читает транскрипты для окна лимита (`scanUsage`, раз в минуту и только пока борд открыт). Биндится на `FLEET_HOST:FLEET_PORT`. Грузит `.env` через `process.loadEnvFile` (Node 22, без зависимостей). Держит таймер уборки зомби (`pruneStale` раз в 5 мин). Запись в SSE-клиентов, heartbeat и чтение тела обёрнуты в try/catch - обрыв сокета не роняет процесс. Всё, что пишется в `fleet.log`, идёт через `log()` с меткой времени. Без внешних зависимостей вообще.
- `focus.js` - **чистое ядро решения «куда вернуть по клику»**: `resolveFocus(card, { launcher, app, isProjectDir })`. Проверка «папка это проект» приходит параметром (как `now` в `state.js`), поэтому матрица случаев (терминал IDE / обычный терминал / нет лаунчера / ничего не известно) покрыта тестами без файловой системы. Здесь же живёт фолбэк `open -a <app> <cwd>`, когда CLI-лаунчера на машине нет.
- `guards.js` - **чистое ядро ограничителей**: `buildAllowLists()` собирает разрешённые Host и Origin, `isAllowedHost()` / `isCrossSite()` решают, пускать ли запрос, `boundedKey()` даёт ключ для счётчика с ограниченным числом строк. Вынесено отдельно, потому что оба ограничения коварны одинаково: если их снять, на вид ничего не сломается - борд продолжит работать, просто наружу утечёт содержимое сессий или процесс начнёт пухнуть. Всё чистое, покрыто тестами.
- `usage.js` - **чистое ядро окна лимита**: `collectStamps(chunk, stamps)` вытаскивает метки времени запросов из куска транскрипта, `foldStamps()` сворачивает их в текущее окно, `describeWindow()` готовит его для борда, `isFreshTranscript()` решает, стоит ли открывать файл. Лимит привязан к **аккаунту, а не к проекту**: все сессии во всех папках плюс claude.ai жгут одну квоту, поэтому окно на борде одно и живёт в шапке. Точной телеметрии лимита нет (как и у статусов) - считаем по локальным транскриптам `~/.claude/projects/**/*.jsonl`, где у каждой записи ассистента есть `timestamp`. Расход в токенах отсюда НЕ считаем: сессии из браузера и с телефона в локальные файлы не попадают, и число было бы занижено незаметно для глаза.
- `state.js` - **чистое ядро**, `applyEvent(sessions, event, now)` маппит событие хука в карточку сессии (статус, задача, текущая активность, `createdAt` - момент первого события для «возраста», `waitingSince` - момент входа в ожидание); `pruneStale(sessions, now, staleMs)` отсекает протухшие карточки. Никаких side effects - тут вся логика, которую покрываем тестами.
- `public/index.html` - страница борда. Один файл, инлайн CSS/JS. Живой фон (дрейфующие пятна + тех-сетка + зерно), сонар-логомарк (краснеет при "ждут тебя").

  **Две формы, а не одна.** Ждущая сессия это карточка (`.card`), работающая - плотная строка (`.row`); общий класс `.unit` держит цвет статусной полоски и поведение (клик, клавиатура, протухание, кнопка удаления). Так сделано потому, что вес на борде должен идти за требованием действия: раньше обе секции рисовались карточками, ждущая карточка растягивалась сеткой в 5 колонок и оказывалась **мельче** рабочих - приоритет был инвертирован. Теперь секция "ждут тебя" это карточки до 600px (`repeat(auto-fill, minmax(460px, 600px))`, `justify-content: start`), а "в работе" - строки высотой ~50px. Потолок дорожки именно 600, а не больше: `auto-fill` считает число колонок по **максимуму** дорожки, и при 640 на мониторе 1900px влезало бы две карточки вместо трёх.

  **Колонки строк фиксированы по ширине** (`92px 1fr 340px 162px 96px 116px`), а не `auto`. Каждая строка это отдельный grid, поэтому `auto`-колонка меряется по своему содержимому - бейджи, возраст и метки терминала разъезжались бы по строкам, и весь смысл плотного режима (читать статусы столбцом, не вчитываясь) пропадал. Тянется только колонка задачи.

  Строки сгруппированы по проектам заголовком `.ghead` (монограмма, имя 19px/750, счётчик, тонкая линейка). Имени проекта в самой строке **нет** - оно в заголовке группы, иначе повторялось бы в каждой строке.

  **Голого цветного маркера у группы быть не должно.** WebStorm и Alacritty уже красят окружение своими цветами, и второй такой же язык цвета на борде спорит с ними. Вместо точки стоит монограмма-аватар `projectMark()`: инициалы (режем и по разделителям, и по камелкейсу: `claude-fleet` → CF, `LearningMy` → LM) плюс приглушённый оттенок. Оттенок выводится из имени папки, а не из порядка в списке, иначе знак проекта менялся бы при появлении сессии в соседнем проекте и глаз перестал бы его запоминать.

  **Движение на борде значит «нужен ты».** Анимации остались только у ожидания: `breathe` у красной карточки, `ping` у заголовка секции и сонар логомарки (`.mark.alert`, без класса кольца просто не анимируются). У активных строк полоска статична: бегущий градиент был постоянной вознёй на периферии зрения, которая ничего не сообщала. Фоновые пятна и точка `live` тоже статичны - см. «Цена анимации» ниже. Новую бесконечную анимацию вне ожидания не добавлять.

  **Цена анимации известна, не гадать.** Борд стоит открытым сутками на втором мониторе, поэтому кадр стоит денег: замерено на стенде (отдельный профиль Chrome, свой GPU-процесс, `--disable-backgrounding-occluded-windows`, иначе macOS глушит отрисовку перекрытого окна и замер врёт). Было 45% ядра в покое и 56% при ждущей карточке, стало 5% и 15%; 5% это floor - ровно столько ест пустая вкладка `about:blank`, то есть в покое борд не стоит ничего сверх самого браузера.

  Виноваты были не «тяжёлые эффекты», а анимация неправильных свойств. **Анимировать только `transform` и `opacity`** (композит, GPU) и никогда `box-shadow`, `background`, `border-color`, `filter` (перерисовка каждый кадр):
  - дрейф пятен через `transform` со `scale()` заставлял пересчитывать `blur(95px)` на трёх слоях по 50vw каждый кадр - 54% ядра круглосуточно ради текстуры. Пятна статичны, blur растрируется один раз;
  - `breathe` пульсировал `box-shadow` по периметру карточки шириной 600px - 21% ядра на одну карточку. Свечение вынесено в отдельный слой `.glow`, анимируется его `opacity`; тень внутренняя, потому что `.card` обрезает содержимое (`overflow: hidden`);
  - `ping` и `livePulse` пульсировали спред `box-shadow` у точек 7-8px. Размер не спасает: `ping` стоил 13%. Кольцо переведено на псевдоэлемент с `transform: scale`, у `live` пульсация убрана совсем - связь читается цветом;
  - `backdrop-filter` шапки пересчитывался каждый кадр, потому что под ним двигались пятна. Заменён непрозрачным фоном;
  - сонару добавлен `will-change: transform, opacity`: без своего слоя обводка с `border-radius` рерастеризовывалась при масштабировании (10%).

  Мерить цену анимации «на глаз» по одному прогону нельзя вдвойне: пока `breathe` и сонар были дорогими, `ping` в замере выглядел бесплатным и проявился только после их починки.

  Фон и поверхности идут лесенкой (`--bg` → `--surface` строки → `--surface-2` карточки). Борд дважды уезжал в слишком тёмное; видимый фон задаёт **радиальный градиент в `.bg` поверх `body`**, поэтому осветлять надо именно его внешний цвет - он занимает низ и края экрана, а `--bg` почти не виден.

  Многоточие в чипе инструмента висит на внутреннем `.tt`, а не на `.tool`: `text-overflow` не действует на flex-контейнер, и длинная команда обрубалась ровно по букве, выглядя как баг рендера.

  **Окно лимита стоит в шапке одной плашкой** (`.win`, рядом с `live`): «до сброса лимита Claude **4 ч 31 мин** в 19:47», а после истечения - «лимит Claude свежий · счётчик пойдёт со следующего запроса». Не в карточке, потому что лимит у аккаунта общий и в каждой строке это было бы одно и то же число. Цвет нейтральный намеренно: красное на борде означает «нужен ты», а окно это справка. Формулировка прямая, без внутренней терминологии: «окно до 19:34» не объясняло ни чьё окно, ни что случится в 19:34. Сервер шлёт только границы, обратный отсчёт двигает `paintUsage` в общем секундном тике, а время конца окна считается один раз при обновлении данных и лежит в `dataset` - `toLocaleTimeString` в посекундном тике не нужен. У `.win` обязателен `[hidden] { display: none }`: `display` из класса перебивает атрибут `hidden` по специфичности, и без этого правила в шапке висела пустая пилюля-призрак, пока сервер не прислал окно.

  Когда ждущих нет, но сессии есть, на месте красной секции показывается спокойная плашка `.calm` («Никто не ждёт»). Без неё спокойный борд выглядел ровно так же, как борд, на который просто не с той стороны посмотрели.

  Масштаб рассчитан на взгляд с расстояния - борд живёт на втором мониторе, а не под носом: базовый шрифт 16px, имя проекта в карточке 19px, заголовок группы 16.5px, задача в строке 15px, строка ~52px высотой. Мельчить нельзя, даже если «влезает больше»: борд уже один раз уезжал в слишком мелкое. Карточка и строка это `div[role=button]`, а не `<button>`: внутрь вложена кнопка удаления, а кнопку в кнопку нельзя - поэтому Enter/Space обрабатываются вручную (`keydown` на `board`), иначе борд перестал бы работать с клавиатуры. Метка терминала - брендовым цветом маркера (`termColor` / `TERM_COLORS`).

  Рендер точечный: элемент создаётся один раз на сессию (реестр `cardEls`) и дальше только переставляется между слотами и обновляется внутри по своей сигнатуре; скелет секций перестраивается, только когда меняется сама раскладка (`lastLayout`). Так `:hover` не гаснет под курсором (а кнопка удаления показывается именно по ховеру), не сбрасывается фокус клавиатуры и клик не промахивается. Единственный случай пересоздания элемента - смена формы (`entry.shape`), когда сессия переезжает между секциями: внутри строки иначе остался бы markup карточки. Исчезнувшие сессии выкидываются из реестра (`forgetGoneCards`), иначе он растёт до перезагрузки страницы. Раз в секунду `tickTimes` двигает время/возраст на месте и подсвечивает протухшие; время последнего события лежит на самом элементе (`dataset.ts`), потому что у строки нет подписи «N сек назад». Динамический favicon рисуется на canvas: краснеет и показывает число, когда кто-то ждёт (сигнал на иконке фоновой вкладки).
- `hooks/report.sh` - неблокирующий форвардер: пробрасывает stdin (JSON события) в `/event`. Сам находит свою папку (`BASH_SOURCE`), порт берёт из `.env`. Короткий таймаут, всегда `exit 0`.
- `scripts/board.sh` - открывает борд отдельным окном-приложением Яндекс Браузера (`--app=<url>`). Годится и для рук, и для автозапуска при логине: ждёт сервер до 20 сек (`FLEET_BOARD_WAIT`) и не поднимает второе окно поверх уже открытого борда (`--force`, если окно нужно именно новое). Два пути запуска браузера, и это не дублирование: **запущенному** браузеру `--app` отдаёт прямой вызов бинаря (процесс сразу выходит; через `open -na` нельзя - `-n` поднял бы второй экземпляр со своим профилем), а **холодный** старт идёт через `open -b ru.yandex.desktop.yandex-browser --args` (см. инвариант ниже). Если Яндекса нет - фолбэк на браузер по умолчанию.
- `test/state.test.js`, `test/focus.test.js`, `test/guards.test.js`, `test/usage.test.js` - `node --test`, покрывают все четыре чистых ядра.
- `scripts/install.sh` / `scripts/uninstall.sh` - установка и снятие: `.env`, хуки в `~/.claude/settings.json` (мерж через node, с бэкапом, чужие хуки не трогаются), plist из текущего пути репозитория и абсолютного пути node, перезагрузка агентов. Агентов два: сервер и (при `FLEET_AUTOOPEN=1`) `<label>-board`, разовый `RunAtLoad` без `KeepAlive`, который при логине зовёт `board.sh`. Выключение автозапуска ранее поставленный агент снимает, `uninstall.sh` гасит оба. Идемпотентно, гоняется повторно после переезда папки или обновления node.
- `.env` / `.env.example` - конфиг (реальный `.env` в `.gitignore`, шаблон закоммичен).

## Конфиг (`.env`)

Машинно-зависимые литералы и настройки живут в `.env`, не в коде. Node 22 читает файл сам.

| Переменная | Дефолт | Что |
|------------|--------|-----|
| `FLEET_PORT` | `4319` | порт сервера; его же читает `report.sh` (единый порт) |
| `FLEET_HOST` | `127.0.0.1` | хост привязки, только localhost |
| `FLEET_ALLOWED_HOSTS` | пусто | доп. значения заголовка `Host` через запятую (смотреть борд с планшета). Пусто = только localhost |
| `FLEET_STALE_HOURS` | `6` | порог простоя карточки: и при восстановлении с диска, и для рантайм-уборки зомби (`pruneStale` раз в 5 мин) |
| `FLEET_TRANSCRIPTS` | `~/.claude/projects` | папка транскриптов Claude Code, по ним считается окно лимита (только чтение) |
| `FLEET_USAGE_HOURS` | `5` | длина окна лимита; не наша настройка, а свойство тарифа - поменяют, поправишь одну строку |
| `FLEET_USAGE_ALIGN_MIN` | `30` | до какой границы округляется вниз старт окна (0 - не округлять) |
| `FLEET_WEBSTORM` | `/usr/local/bin/webstorm` | путь к CLI-лаунчеру WebStorm (на разных машинах разный) |
| `FLEET_WEBSTORM_APP` | `WebStorm` | имя приложения для фолбэка `open -a` |
| `FLEET_AUTOOPEN` | `1` | ставить ли агент автооткрытия борда при логине; читает только `install.sh` |
| `FLEET_BOARD_WAIT` | `20` | сколько секунд `board.sh` ждёт ответа сервера при автозапуске, прежде чем сдаться (на холодной загрузке системы node поднимается дольше обычного) |

## Ключевые инварианты (не ломать)

- **`report.sh` обязан быть безопасным для чужих сессий**: `exit 0` всегда, пустой stdout, микро-таймаут. Он висит глобально на каждом вызове тула во всех проектах - любая его ошибка/задержка/вывод ударит по всем сессиям Claude Code. Не добавлять сюда логику, только форвардинг.
- **`state.js` держать чистым** (без IO, без Date.now внутри - время приходит параметром). Вся новая логика карточек - сюда, с тестом.
- **Машинно-зависимые пути/настройки - в `.env`, не литералами в коде.** Путь к WebStorm, порт, хост и т.п. читаем из env с дефолтами.
- **Никаких внешних зависимостей** без явной причины. Тулза должна стартовать мгновенно и есть ~30-60 МБ, не больше. Никакого Electron, никакого bundler.
- **Только localhost, и `Host` проверяем.** Сервер биндится на `FLEET_HOST` (дефолт `127.0.0.1`), но одной привязки мало: при DNS rebinding страница злого сайта резолвит свой домен в `127.0.0.1` и становится same-origin с бордом, после чего читает `/stream` - а там все промпты, пути проектов и команды Bash. Поэтому `isAllowedHost()` пускает только localhost-хосты (плюс `FLEET_ALLOWED_HOSTS`), а `isCrossSite()` рубит мутирующие запросы с чужой страницы по `Sec-Fetch-Site`/`Origin`. `report.sh` ходит через curl - у него этих заголовков нет, он проходит. Проверки снимать нельзя.
  **Список Origin выводится из того же списка хостов** (`buildAllowLists` в `guards.js`), а не задаётся отдельно. Пока Origin был захардкожен на localhost, борд с планшета через `FLEET_ALLOWED_HOSTS` открывался на просмотр, но клик по карточке и удаление ловили 403: `isCrossSite` не узнавал собственную же страницу. Добавляешь способ обратиться к борду - добавляй и Host, и Origin, иначе фича будет работать наполовину.
- **Тело события ограничено** (`MAX_BODY` 1 МБ, жёсткий предел 32 МБ): в `tool_response` может лежать содержимое большого файла. Сверх лимита в память не копим, но поток дочитываем - оборвать сокет значит лишить отправителя внятного ответа. Отброс пишется в лог, иначе карточка молча залипнет на прошлом статусе.
- **Уведомления не навязываются.** Выключены по умолчанию, состояние в `localStorage`, всегда `silent: true`, только про новые ожидающие сессии, один общий `tag` (новое заменяет старое, а не копится). Первый снапшот после открытия борда уведомлений не даёт - это текущее положение дел, а не события. Борд задумывался как тихий сигнал, и таким должен остаться по умолчанию.
- **Ничто в памяти не растёт без предела.** Проверено нагрузкой: 40 000 событий и 300 подключений борда дают плато (60 → ~70 МБ в реальном темпе, ~105 МБ под штормом в 12 тыс. соб/с), утечек нет. Оба счётчика событий - `unknownEvents` и разбивка `stats.byEvent` для `/stats` - ограничены по числу ключей через `boundedKey()` (`MAX_UNKNOWN_KINDS` и `MAX_EVENT_KINDS`), лишние имена сваливаются в строку «прочие». Без ограничения поток событий с уникальными именами раздувал Map без предела: замерено, 12 000 разных имён давали 82 МБ и рост не останавливался, с ограничением RSS выходит на плато 73 МБ. `stats.byEvent` был пропущен при первой правке именно потому, что выглядел безобидной диагностикой - любую новую накапливающую структуру ограничивать сразу, даже если она «просто для счётчиков».
- **Старт окна лимита выравнивается вниз до получаса.** Claude открывает окно не по секунде первого запроса, а по ближайшей границе получаса. Сверено с экраном `/usage`: первая активность дня в 09:32:40, первый ответ в 09:34, официальный сброс в 19:30 - то есть цепочка 09:30 → 14:30 → 19:30, а без выравнивания борд показывал 19:34. Округление живёт в `foldStamps` (при открытии окна), а не в показе: от округлённого старта считается граница следующего окна, иначе метка сразу после сброса попала бы в уже закрытое окно и расхождение копилось бы с каждым блоком. Если борд начнёт расходиться с `/usage` - сначала сверить именно эту границу, а не искать потерянные события.
- **Чтение транскриптов идёт в один буфер на процесс.** Свежие транскрипты за десять часов весят под 50 МБ, и наивные подходы к их разбору бьют по памяти втрое сильнее, чем кажется. Замерено снаружи (`ps`, без опроса `/stats` - опрос сам искажает картину): пик RSS при `Buffer` на весь остаток файла 96 МБ, при чтении потоком с `encoding: 'utf8'` 133 МБ (поток аллоцирует новый буфер на каждый кусок, и мусор копится быстрее, чем работает GC), при чтении в переиспользуемый `READ_BUFFER` 69 МБ против 61 МБ у версии без фичи. Декодируем только саму дату, а маркеры ищем буферным `indexOf` - нужного текста в транскрипте меньше процента. Читать файлы «умнее» (хвостом с ранней остановкой на старых записях) смысла нет: замерено, 48 МБ из 65 и так относятся к последним десяти часам.
- **Транскрипты читаются, только пока борд открыт.** Без единого SSE-клиента `scanUsage` не запускается вовсе: борд стоит открытым сутками, но когда его закрыли, процесс обязан стоять на нуле. При подключении первого клиента скан идёт сразу, дальше раз в минуту - чаще незачем, обратный отсчёт тикает на фронте сам.
- **Незнакомые события хука считаем и показываем.** Схема событий Claude Code не наша: обновится - и часть статусов молча перестанет обновляться. `isHandledEvent()` в `state.js`, счётчик в `server.js`, янтарный бейдж в шапке борда.
- **Цена события известна, не гадать.** Замерено на живой работе через `/stats`: `PostToolUse` в среднем 20 КБ и до 54 КБ (в `tool_response` лежит результат инструмента), `PreToolUse` - 2.9 КБ. То есть тяжелее в разы, но до лимита `MAX_BODY` (1 МБ) запас в 20 раз, и по loopback такие тела уходят за миллисекунды - `--max-time 0.5` в `report.sh` им не помеха. Если появится подозрение на потерянные события, первым делом смотреть `/stats`, а не догадки.
- **`report.sh` не должен форкать процессы.** Порт из `.env` читается циклом `while read` на чистом bash, путь - через `${BASH_SOURCE[0]%/*}`. Прежние `$(cd .. && pwd)` и `grep|tail|cut|tr` стоили 5 форков на каждый вызов инструмента: 18.5 мс против нынешних 13 мс.
- **Персист пишется атомарно** (`.tmp` + `renameSync`): падение в момент записи иначе оставит обрезанный JSON, а `loadState` молча вернёт `{}` и все живые карточки исчезнут.
- **Персист (`.fleet-state.json`) - страховка, не история.** Переживает рестарт сервера, но при ребуте сбрасывается (сравнение mtime файла с временем загрузки через `os.uptime()`). Не превращать в лог завершённых сессий.
- **Зомби-карточки чистятся в рантайме.** `SessionEnd` приходит только на аккуратный `/exit`; при закрытии окна терминала / kill / крэше его нет. Поэтому таймер в `server.js` раз в 5 мин прогоняет `pruneStale` с порогом `STALE_MS` (тот же `FLEET_STALE_HOURS`) и вещает изменения. Логику «что протухло» держим в `state.js` (чистая функция), сам таймер - в `server.js`.
- **Браузер нельзя запускать из-под launchd прямым вызовом бинаря.** Пока Яндекс уже работает, прямой вызов безобиден: процесс отдаёт `--app` живому браузеру и сразу выходит. Но на холодную он сам становится главным процессом браузера и наследуется тем, кто его позвал: у launchd-агента это значит, что job числится живым всё время жизни браузера, а любой `launchctl bootout` - включая повторный прогон `install.sh` - закрывает Яндекс со всеми вкладками пользователя. Поэтому холодный старт только через `open -b <bundle-id> --args`, плюс `AbandonProcessGroup` в plist как страховка. Проверено: `ppid` поднятого браузера равен 1, а не агенту.
- **Нулю в `boards` верить сразу нельзя.** `install.sh` перезапускает сервер прямо перед стартом агента борда, рестарт рвёт все SSE, и уже открытое окно возвращается в счётчик лишь через пару секунд. Пока `board.sh` читал `/stats` один раз, установка исправно дублировала окно борда. Ноль перепроверяется 6 секунд (`FLEET_BOARD_SETTLE`), непустой ответ принимается сразу. Любая будущая проверка «открыто ли уже» обязана учитывать этот же лаг переподключения.
- Правится только `~/.claude/settings.json` (там хуки). Файл `~/.claude.json` не трогать.

## Что показывает карточка

- **статус** (приблизительно из типа события, точной телеметрии у хуков нет): `ready` (SessionStart) · `thinking` (UserPromptSubmit / PostCompact) · `tool` (PreToolUse) · `working` (PostToolUse) · `error` (PostToolUse с ошибкой, PostToolUseFailure) · `compacting` (PreCompact) · `waiting` (Notification / Stop / StopFailure). `SubagentStop` статус НЕ трогает: заканчивается субагент, а сессия работает дальше - пометить её «закончил ход» значит утопить в «ждут тебя» настоящие красные карточки.
- **чего именно ждут** - `note`, текст уведомления из `Notification` («Claude needs your permission to use Bash»). Плюс при `permission`/`question` показывается `tool` + `toolInfo`: видно, на что спрашивают разрешение (`Bash · git push --force`), и решение принимается не вставая. Сбрасывается на любом следующем событии.
- **задача** - последний промпт (`title`, из `UserPromptSubmit`). Служебные инъекции (`<task-notification>`, `<system-reminder>`, слэш-команды, bash-проброс) в заголовок не пишутся - фильтр `isServicePrompt` в `state.js`, чтобы не затирать реальную задачу.
- **активность "над чем сейчас"** - `tool` + `toolInfo` из `tool_input` (какой файл читает/правит, какую команду в Bash, паттерн Grep и т.п. - `toolTarget()` в `state.js`).
- **где живёт** - метка терминала (`terminal`) из `appId` (`terminalName()` в `state.js`): WebStorm / Alacritty / iTerm / Terminal / ...
- **возраст** - «идёт N мин» из `createdAt` (когда карточку впервые увидели), рядом с id. У `waiting` возраст не показываем: время ожидания уже стоит в бейдже, а два времени в узкой карточке съедают имя проекта.
- **сколько ждёт** - у красной карточки время в бейдже («ждёт разрешения · 3 мин»), тикает в `tickTimes`. Считается от `waitingSince`, а НЕ от `updatedAt`: `updatedAt` двигает любое входящее событие (повторный idle-Notification, `SubagentStop`), и пока время брали оттуда, счётчик обнулялся прямо во время ожидания, а карточка проваливалась вниз секции. Секция «ждут тебя» отсортирована так, что дольше всех ждущий сверху: разбираешь самое залежавшееся, и новая красная карточка не сдвигает те, что уже в списке.
- **убрать руками** - кнопка × в углу карточки (видна на ховере) шлёт `DELETE /session/:id`. Нужна для зомби: `SessionEnd` приходит только на аккуратный `/exit`, иначе карточка висит часами до `pruneStale`.
- **протухание** - активная карточка (`thinking`/`tool`/`working`/`error`/`compacting`) без событий дольше `IDLE_MS` (4 мин) тускнеет и показывает «нет активности»: вероятно сессия подвисла или её закрыли. `waiting`/`ready` не трогаем - они законно ждут человека. Это визуальная подсказка на фронте; окончательно зомби убирает `pruneStale` (см. инварианты).

`waiting` собирается в секцию "ждут тебя" (красное) с причиной для бейджа:
- `finished` - Stop, закончил ход
- `permission` - Notification про разрешение
- `question` - Notification-вопрос/простой/AskUserQuestion
- `failed` - StopFailure, ход оборвался ошибкой API и сессия встала сама

Причина берётся из `notification_type` (`permission_prompt` / `idle_prompt` / `agent_needs_input` /
`elicitation_dialog` / `agent_completed`), а разбор английского текста `message` оставлен фолбэком
для версий без этого поля. `auth_success` и прочие информационные уведомления статус не трогают:
раньше любой Notification красил карточку в красное и звал к сессии, которой ты не нужен.
`idle_prompt` на уже ждущей карточке игнорируется целиком - это напоминание о простое, а не новая
причина, и раньше оно подменяло «закончил ход» на «нужен ответ».

## Запуск и тесты

```bash
./scripts/install.sh   # конфиг + хуки + launchd-агент, идемпотентно
node server.js         # или npm start, если хочется руками
node --test            # или npm test
./scripts/board.sh     # открыть борд окном-приложением Яндекс Браузера (--force для второго окна)
./scripts/uninstall.sh # снять агент и свои хуки
```

Автозапуск - launchd-агент `com.rasulkiller.claude-fleet` (см. `install.md`). Логи - `fleet.log`
и `fleet.error.log`. Агент перезапускается только после падения (`KeepAlive` = `Crashed`),
поэтому остановленный вручную остаётся остановленным.

## После изменений

- Тронул `state.js`, `focus.js`, `guards.js` или `usage.js` - прогони `node --test`, добавь/поправь тест на новое поведение.
- Тронул `scripts/install.sh` - проверяй на фейковом `HOME` и своём `FLEET_LABEL` с нерабочим портом в `.env`, а не на живой системе. Обязательно клади в тестовый `settings.json` чужой хук: он должен пережить и установку, и удаление. Нерабочий порт бери привилегированный (`FLEET_PORT=1`): на свободном высоком порту копия сервера реально поднимется и агент борда откроет лишнее окно.
- Тронул `scripts/board.sh` - гоняй все три пути: холодный старт (браузер закрыт), горячий (`--force` при живом браузере) и защиту от дубля. Лишние окна закрывать за собой: `osascript -e 'tell application "Yandex" to close window 1'`.
- Тронул `server.js` - перезапусти процесс: `launchctl kickstart -k gui/$(id -u)/com.rasulkiller.claude-fleet`, проверь борд вживую.
- Тронул `com...plist` (или env в нём) - нужен полный reload: `launchctl bootout ...` + `launchctl bootstrap ...` (kickstart плист не перечитывает).
- Тронул `public/index.html` - сервер отдаёт файл свежим на каждый запрос, достаточно обновить вкладку браузера (Cmd+R). Визуально проверять через headless Chrome по статическому моку (без живого SSE, иначе headless виснет на бесконечном потоке) в изолированной копии (scratchpad, другой порт) - живой сервер и `.fleet-state.json` не трогать.
- Тронул код - обнови `CLAUDE.md` в той же сессии, чтобы дока не расходилась с реализацией (проверяй карту файлов, инварианты, «что показывает карточка»).
- Правило проекта: сначала переименование/выделение метода ради читаемости, комментарий только на "почему".
- **Синтетические события слать только в изолированную копию.** POST в живой `/event` с придуманным `session_id`/`cwd` создаёт настоящую карточку (был случай: замер производительности с `cwd=/tmp` нарисовал на борде проект `tmp`). Для проверок - копия в scratchpad со своим портом, живой борд не трогать.
- Процесс копии убивать по порту (`lsof -ti :4399 | xargs kill`), а не через `pkill -f <путь>`: запущенный как `node server.js` он в списке процессов без полного пути, `pkill` его не находит, и дальше тесты бьют в старую версию.
